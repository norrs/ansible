Recommendation

controlled maintenance window
Proceed to 16.0.1, not 16.0.0. The patch release fixes Dovecot quota handling for aliases that forward externally, which is directly relevant because this deployment has ENABLE_QUOTAS=1 and manages aliases.

Pin the exact 16.0.1 tag for the first deployment. Keep the existing 15.1 image locally until the observation window is complete. Do not combine this with unrelated mail configuration changes.

The v16 base changes from Debian 12 to Debian 13 and Dovecot 2.3 to 2.4. Treat this as a migration even though the application data remains on bind mounts.

Repository audit

Inspected 2026-09-04

Dovecot exposure is limited

No custom dovecot.cf, LDAP, FTS/Solr/Xapian, mail-crypt, or dhparams.pem files were found. The largest v16 breaking changes therefore do not directly map to tracked configuration.

Custom Postfix needs a smoke test

postfix-main.cf binds outbound SMTP to the server IPv4/IPv6 addresses. postfix-master.cf forces Amavis handoff over loopback. Preserve both and validate configuration plus outbound delivery.

Fail2Ban is customized

The private jail uses nftables-allports, enables Dovecot, Postfix mode=extra, and a long-lived manual jail. v16 updates Fail2Ban and pins Dovecot/Postfix jails to file backends; verify all three jails load.

Use the new healthcheck

The Compose file overrides health with an ss | grep probe and zero retries. v16 includes dms-healthcheck; remove the override so Docker uses the image-defined probe.

Spam and quota paths are active

ClamAV, Amavis, SpamAssassin, Postgrey, junk movement, and quotas are enabled. Test inbound spam classification, normal delivery, and quota lookup—not only SMTP connectivity.

Environment template is stale

DMS_DEBUG was removed long ago and ONE_DIR is absent from the v16 template. The removed v16 variable SA_SPAM_SUBJECT appears only in a comment, not as configured state. Rebase comments/options while preserving intentional values.

Execution plan

Change each item to Done as evidence is collected

1Review official v16 documentation

  • Read the v16.0.0 and v16.0.1 changelog sections.
  • Confirm the release image is ghcr.io/docker-mailserver/docker-mailserver:16.0.1.

2Audit tracked deployment configuration

  • Identify custom Dovecot, Postfix, Fail2Ban, TLS, LDAP and spam configuration.
  • Compare tracked mailserver.env and Compose settings with the v16.0.1 examples.

3Schedule and freeze the change

  • Choose a low-volume maintenance window and announce expected SMTP/IMAP interruption.
  • Freeze unrelated Ansible, DNS, certificate and mail configuration changes.
  • Assign an operator and rollback decision-maker.

4Capture the live 15.1 baseline

  • Container is healthy; SMTP, submission and IMAP work before the change.
  • Record version, image ID, queue depth, accounts, aliases, disk space and certificate dates.
  • Save effective Postfix, Dovecot and Fail2Ban configuration output outside the container.
Suggested baseline commands on diablo
cd /opt/dms sudo docker compose ps sudo docker inspect --format '{{.Config.Image}} {{.Image}} {{if .State.Health}}{{.State.Health.Status}}{{end}}' mailserver sudo docker logs --since 30m mailserver sudo docker exec mailserver postqueue -p sudo docker exec mailserver setup email list sudo docker exec mailserver setup alias list sudo docker exec mailserver postconf -n sudo docker exec mailserver doveconf -n sudo docker exec mailserver fail2ban-client status sudo docker exec mailserver fail2ban-client status dovecot sudo docker exec mailserver fail2ban-client status postfix sudo docker exec mailserver fail2ban-client status custom df -h /opt/dms sudo docker exec mailserver openssl x509 -in /etc/letsencrypt/live/diablo.norrs.no/fullchain.pem -noout -subject -issuer -dates

5Create and verify a rollback backup

  • The Postfix queue is empty or every queued message is accounted for.
  • A timestamped archive contains config, mail data, state and logs.
  • tar -tzf can read the archive and a checksum is recorded.
  • The existing 15.1 image remains present locally.
Cold-backup commands on diablo
cd /opt/dms sudo docker exec mailserver postqueue -p sudo systemctl stop mailserver sudo tar --gzip --create --file "/opt/dms-backup-$(date +%F-%H%M)-pre-16.0.1.tar.gz" -C /opt/dms docker-data/dms sudo tar --list --gzip --file /opt/dms-backup-YYYY-MM-DD-HHMM-pre-16.0.1.tar.gz | head sudo sha256sum /opt/dms-backup-YYYY-MM-DD-HHMM-pre-16.0.1.tar.gz sudo systemctl start mailserver sudo docker image inspect ghcr.io/docker-mailserver/docker-mailserver:15.1 --format '{{.Id}}'
Replace the timestamp placeholder in verification commands with the actual archive name. A cold backup creates a short extra interruption but avoids a changing Maildir/state tree during the archive.

6Prepare the isolated repository change

  • Change only the image tag from 15.1 to exact 16.0.1.
  • Remove the Compose healthcheck override to inherit dms-healthcheck.
  • Reconcile mailserver.env with the v16.0.1 template while preserving deliberate values.
  • Remove obsolete DMS_DEBUG and ONE_DIR; keep all four persistent bind mounts.
  • Do not add SA_SPAM_SUBJECT; use SPAM_SUBJECT only if a subject prefix is desired.
  • Review and commit a mailserver-only diff so rollback is one revert.
Local validation commands
git diff -- playbooks/mailserver docker compose -f playbooks/mailserver/files/mailserver/compose.yaml config --quiet ansible-playbook --syntax-check -i inventory.yaml playbooks/mailserver/playbook.yaml

7Run the go / no-go preflight

  • Backup and checksum are verified.
  • Baseline mail flow is healthy and the queue is drained.
  • At least 3 GiB free disk space and enough memory/swap for ClamAV are available.
  • The v16.0.1 image can be pulled before downtime starts.
  • Operator has console/SSH access independent of email.
Pre-pull and resource checks on diablo

8Deploy 16.0.1 through Ansible

  • Run only the Diablo mailserver tag.
  • Ansible completes without failed or unreachable tasks.
  • The systemd unit recreates the container rather than merely restarting it.
  • Record actual start and finish times.
Deployment command from the Ansible repository
scripts/play-host.bash diablo mailserver --ask-become-pass
The DMS documentation requires docker compose down / up or a force-recreate. This repository's systemd unit uses down for stop and up --force-recreate for start, satisfying that requirement.

9Validate startup and effective configuration

  • Logs show the 16.0.1 welcome line and no fatal setup errors.
  • Container reaches healthy state using dms-healthcheck.
  • Postfix and Dovecot configuration commands succeed.
  • Fail2Ban loads the Dovecot, Postfix and custom jails.
  • Accounts and aliases match the baseline.

10Exercise end-to-end mail paths

  • Inbound mail from an external provider arrives over SMTP and appears in IMAP.
  • Authenticated submission over 465 or 587 delivers to an external provider.
  • Reply through a managed service alias works; test an external-forward alias if one exists.
  • TLS succeeds on 25, 465, 587, 143 and 993 with the expected certificate.
  • A known spam test follows the expected SpamAssassin/Junk path.
  • Quota reporting and rejection behavior remain correct.
  • MTA-STS-enabled outbound delivery shows no new TLS-policy errors.
Useful checks

Do not paste passwords into this tracker. Store only message IDs, timestamps, sender/recipient domains and observed outcomes.

11Observe for 24 hours

  • Health remains stable with no restart loop.
  • Queue returns to normal and has no unexplained deferred mail.
  • No repeated Dovecot, quota, Amavis, ClamAV or Fail2Ban errors appear.
  • Normal login, delivery and junk-folder behavior is confirmed by at least one real user.
Observation checks

12Close the change

  • Record the final image ID and the upgrade commit.
  • Export this tracker state and keep it with the change record.
  • Retain the pre-upgrade archive according to backup policy.
  • Only after the observation window, decide whether to prune the 15.1 image.

Decision gates

Continue / accept

  • Container becomes healthy within 5 minutes.
  • No fatal startup or config errors.
  • Inbound, authenticated outbound, IMAP and alias tests pass.
  • Queue drains and Fail2Ban jails load.

Stop / roll back

  • Health stays unhealthy after 5 minutes.
  • Dovecot/Postfix configuration fails or service loops.
  • Authentication, mail delivery, quota, or TLS fails.
  • Queue grows with unexplained deferrals.

Rollback runbook

keep immediately available
  1. Stop testing and preserve logs plus message IDs.
  2. Revert the isolated mailserver upgrade commit so the tag is 15.1 and the old healthcheck/env configuration is restored.
  3. Run scripts/play-host.bash diablo mailserver --ask-become-pass to recreate the 15.1 container.
  4. Repeat startup, account, alias, TLS and mail-flow checks.
  5. Do not restore mail data by default. A full pre-upgrade restore would discard messages accepted after the backup. Restore persistent data only if the old image cannot operate on it, after preserving the post-upgrade tree for reconciliation.
Emergency image rollback if the Git revert is not yet available
cd /opt/dms sudo sed -i 's#docker-mailserver:16\.0\.1#docker-mailserver:15.1#' compose.yaml sudo systemctl restart mailserver sudo docker compose ps sudo docker logs --since 10m mailserver
The emergency edit is temporary drift from Ansible. Follow it by reverting the repository change and reapplying the mailserver playbook.
